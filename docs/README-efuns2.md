# Driver efun 缺漏報告
##共發現 22 個 fs/adm/** 需要但 driver 尚未實作的 efun，按優先順序分類：

🔴 高優先（影響大量檔案）

### Security / Identity

- seteuid / getuid / geteuid — 幾乎所有 daemon 都用，是 LPC 權限控制的核心

### String / Parsing

- sscanf — 38 個檔案用，解析字串的基礎 efun
- undefinedp — 35 個檔案，等同 !efun::undefinedp() 的 null check
- file_name — 17 個檔案，base_name 的同義詞（driver 有 base_name，但很多程式碼叫 file_name）

### Mapping

- map_delete — 24 個檔案（⚠ driver 已有 m_delete，加 alias 即可）
- allocate_mapping — 11 個檔案（driver 有 m_add 但沒有這個初始化版本）

🟡 中優先

- wizardp — 19 個檔案，判斷是否為 wizard
- new — 12 個檔案，clone_object 的語法糖
- notify_fail — 9 個檔案，command 失敗訊息
- foreach — 9 個檔案，語言層面的迴圈結構（可能需要 parser 支援而非 efun）

🟢 網路/socket（獨立模組）
- socket_create / socket_write / socket_close / socket_connect / socket_error / send_udp / udp_port / htonn / query_host_name — 這些只在 daemons/network/ 和 intermud/ 使用，可以獨立實作成網路模組。

補充： map_delete 最快解決方式是在 driver 加一個 m_delete 的 alias；stringp / mapp / pointerp / intp / objectp 已在 efun_type.go 實作，沒問題。
